# استيراد محتوى السيناريو (استيراد سريع بالـ JSON)

هذا الدليل يشرح كيفية إدخال بيانات محتوى السيناريو (الشاشات + الخيارات + التغذية الراجعة) بشكل سريع عبر الـ API بدلاً من إضافة كل شاشة يدوياً من الداش بورد.

---

## الـ Endpoints

| الطريقة | المسار | الوصف |
|--------|--------|--------|
| `POST` | `/api/v1/admin/scenarios/import` | **استيراد كامل**: إنشاء سيناريو جديد + استيراد الشاشات والخيارات في طلب واحد (لا تحتاج معرف سيناريو). |
| `POST` | `/api/v1/admin/scenarios/{id}/import-content` | **استيراد الشاشات فقط**: إضافة أو استبدال محتوى سيناريو **موجود مسبقاً** (تحتاج معرف السيناريو). |

- **استيراد كامل** (`scenarios/import`): صلاحية إنشاء السيناريوهات. يُنشئ السيناريو (مع level_id، العنوان، الوصف، is_free) ثم يضيف الشاشات تلقائياً. `is_published` يكون `false` حتى تنشره لاحقاً.
- **استيراد المحتوى فقط** (`scenarios/{id}/import-content`): صلاحية تحديث السيناريوهات. السيناريو يجب أن يكون موجوداً.

---

## 1. استيراد كامل (إنشاء سيناريو + شاشات) — `POST scenarios/import`

في طلب واحد ترسل بيانات السيناريو **و** مصفوفة الشاشات. النظام ينشئ السيناريو، يضيفه إلى Level Track، ثم يستورد الشاشات والخيارات.

### هيكل الـ Body

```json
{
  "level_id": 1,
  "title": "عنوان السيناريو",
  "description": "وصف اختياري",
  "is_free": false,
  "screens": [
    {
      "question_text": "نص السؤال + السياق.",
      "explanation": "شرح اختياري بعد الإجابة",
      "options": [
        {
          "option_text": "نص الخيار",
          "feedback_text": "التغذية الراجعة",
          "next": "2"
        },
        {
          "option_text": "خيار ينتهي السيناريو",
          "feedback_text": "نهاية السيناريو",
          "next": "end"
        }
      ]
    }
  ]
}
```

| الحقل | مطلوب | الوصف |
|-------|--------|--------|
| `level_id` | نعم | معرف المستوى. |
| `title` | نعم | عنوان السيناريو. |
| `description` | لا | وصف السيناريو. |
| `is_free` | لا | إذا لم يُرسل يكون `false`. |
| `screens` | نعم | نفس مصفوفة الشاشات الموضحة أدناه (هيكل الشاشات والخيارات). |

الاستجابة تحتوي على السيناريو المنشأ مع الشاشات، وعدد الشاشات المُنشأة.

---

## 2. استيراد الشاشات فقط — `POST scenarios/{id}/import-content`

للسيناريو **الموجود مسبقاً** (معرف السيناريو في المسار). ترسل فقط `replace` و `screens`. نفس هيكل `screens` المستخدم في الاستيراد الكامل.

---

## هيكل الشاشات والخيارات (`screens`)

**ترتيب الشاشات في المصفوفة = ترتيبها في السيناريو.** النظام يولد تلقائياً لكل شاشة رمزاً (code) بالصيغة **"الشاشة 1"**, **"الشاشة 2"**, **"الشاشة 3"** ... حسب موقعها في `screens`. لا تحتاج لإرسال `code` من طرفك.

```json
{
  "replace": false,
  "screens": [
    {
      "question_text": "نص السؤال + السياق (يمكن أن يكون متعدد الأسطر).",
      "explanation": "شرح اختياري بعد الإجابة",
      "options": [
        {
          "option_text": "نص الخيار (أ)",
          "feedback_text": "التغذية الراجعة لهذا الخيار",
          "next": "2"
        },
        {
          "option_text": "نص خيار آخر (مثلاً العودة للشاشة 1)",
          "feedback_text": "تغذية راجعة",
          "next": "1"
        },
        {
          "option_text": "خيار ينتهي السيناريو",
          "feedback_text": "نهاية السيناريو",
          "next": "end"
        }
      ]
    }
  ]
}
```

### الحقول

| الحقل | مطلوب | النوع | الوصف |
|-------|--------|-------|--------|
| `replace` | لا | `boolean` | إذا `true` يُحذف كل محتوى السيناريو الحالي (أسئلة + خيارات) ثم يُضاف المحتوى الجديد. إذا `false` أو غير موجود يُضاف المحتوى فوق الموجود (بدون حذف). |
| `screens` | نعم | `array` | مصفوفة الشاشات **بالترتيب** (أول عنصر = الشاشة 1، ثاني عنصر = الشاشة 2، ...). |
| `screens[].question_text` | نعم | `string` | نص السؤال (يمكن أن يتضمن السياق + السؤال في حقل واحد، ويمكن استخدام `\n` للأسطر الجديدة). |
| `screens[].explanation` | لا | `string` | شرح اختياري يظهر بعد الإجابة. |
| `screens[].options` | نعم | `array` | خيارات الإجابة لهذه الشاشة. |
| `screens[].options[].option_text` | نعم | `string` | نص الخيار. |
| `screens[].options[].feedback_text` | لا | `string` | التغذية الراجعة بعد اختيار هذا الخيار. |
| `screens[].options[].next` | لا | `string` | ماذا يحدث بعد هذا الخيار: رقم الشاشة التالية `"1"`, `"2"`, `"3"` ... (للعودة للشاشة الأولى مثلاً نضع `"1"`) أو `"end"` (نهاية السيناريو). |

### قيم `next`

| القيمة | المعنى |
|--------|--------|
| `"1"`, `"2"`, `"3"` ... | الانتقال إلى الشاشة ذات الرقم التسلسلي (أول عنصر في المصفوفة = 1، ثاني = 2، ...). للعودة لنفس الشاشة أو لأي شاشة سابقة نضع رقمها فقط. |
| `"end"` أو `null` أو `""` | نهاية السيناريو (لا شاشة تالية). |

## طريقة الاستخدام السريعة

1. **إنشاء السيناريو من الداش بورد** (إن لم يكن موجوداً): أضف سيناريو جديد واختر المستوى، ثم احفظ وخذ الـ `id`.
2. **تجهيز النص**: قسم النص إلى شاشات؛ كل شاشة = سؤال واحد + خيارات مع التغذية الراجعة واتجاه الانتقال (`next`).
3. **بناء الـ JSON**: استخدم المثال أعلاه كقالب؛ رتّب الشاشات في `screens` بالترتيب المطلوب وغيّر `question_text` و `options` و `next` (رقم الشاشة: 1، 2، 3 … أو `end` للنهاية) حسب المحتوى. للعودة لشاشة معيّنة استخدم رقمها فقط (مثل `"1"`).
4. **الطلب**:  
   `POST /api/v1/admin/scenarios/{id}/import-content`  
   مع `Content-Type: application/json` والـ body هو الـ JSON.
5. إذا أردت **استبدال المحتوى بالكامل** ضع `"replace": true`. إذا أردت **إضافة شاشات فقط** اترك `replace` أو ضعه `false`.

## الاستجابة الناجحة

```json
{
  "success": true,
  "message": "تم استيراد 11 شاشة بنجاح",
  "data": {
    "created_questions": 11,
    "scenario": { ... }
  }
}
```

## أخطاء شائعة

- **السيناريو غير موجود**: تأكد أن `{id}` في الرابط يطابق سيناريو موجود.
- **`screens` فارغ**: يجب إرسال مصفوفة `screens` فيها عنصر واحد على الأقل.
- **`next` يشير لشاشة غير موجودة**: تأكد أن رقم الشاشة في `next` (مثل `"2"`, `"3"`) يطابق ترتيب الشاشات (أول شاشة = 1، ثانية = 2، ...).
- **تدفق غير صالح**: بعد الاستيراد يتم التحقق من التدفق (مثلاً عدم وجود deadlock). إذا فشل التحقق تُرجع رسالة خطأ مناسبة.

باستخدام هذا الـ endpoint يمكنك إدخال بيانات السيناريو بسرعة عبر نسخ/لصق وتعديل JSON بدلاً من إدخال كل شاشة من واجهة الداش بورد.
